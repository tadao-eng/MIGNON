# haiku-checker

自作俳句が大会応募に耐える品質かを、投句前にまとめて点検するコマンドラインツールです。
自動生成は行わず、**ユーザーが入力した句の評価**に特化しています。

1. **歳時記照合** — 季語の検出と季節の特定、季重なり／季違いの検知、季節外れの警告
2. **客観的評価・添削** — LLM による 100 点満点のスコアリングと、伝統派／現代派それぞれの視点からの講評・添削案
3. **類似句チェック** — 有名句コーパスと Web 検索による類句・盗作疑いのリスク判定

## セットアップ

```bash
cd haiku-checker
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[reading,web]"  # reading = janome（読み推定）, web = ブラウザ版
cp .env.example .env             # API キーを記入
haiku build-db                   # data/*.json から SQLite を構築
```

環境変数：

| 変数 | 用途 | 必須 |
|---|---|---|
| `ANTHROPIC_API_KEY` | ② 評価・添削エンジン | 評価を使う場合 |
| `TAVILY_API_KEY` または `SERPER_API_KEY` | ③ Web 検索による類句チェック | 任意 |

キーが無い場合、その機能だけをスキップして残りは通常どおり動きます
（`--no-llm` / `--no-web` で明示的に無効化もできます）。

## 使い方

```bash
# 基本
haiku check "万緑の 中や吾子の歯 生え初むる"

# 上五／中七／下五をスペースで区切ると分割が確定する（推奨）
haiku check "古池や 蛙飛びこむ 水の音"

# 漢字の読みを明示する（文語・難読語で音数がずれるときに）
haiku check "万緑の 中や吾子の歯 生え初むる" --yomi "ばんりょくの なかやあこのは はえそむる"

# 当季雑詠：投句時期と季語の季節が合っているかを見る
haiku check "雪の日の駅" --season 夏
haiku check "雪の日の駅" --date 2026-07-20      # 月から季節を推定

# オフラインで構造と季語だけ見る
haiku check "..." --no-llm --no-web

# 機械可読出力
haiku check "..." --json

# 一括評価（1 行 1 句、`#` 始まりはコメント）
haiku batch submissions.txt

# 季語を引く
haiku kigo 月
haiku kigo --season 新年 --category 行事
```

## ブラウザで使う

```bash
pip install -e ".[web]"
haiku serve                  # http://127.0.0.1:8000/
```

CLI と同じ解析モジュールをそのまま使うので、**歳時記照合・LLM 評価・Web 検索・janome の
読み推定まで全機能がブラウザから使えます**。API キーはサーバー側にのみ置き、フロントエンドには
一切渡しません（`/api/status` はキーの有無だけを返します）。

画面は 2 段階で描画されます。定型・歳時記・ローカル類句照合は即座に返り、時間のかかる
LLM 評価だけが後から差し込まれるので、待ち時間中も先に読める結果が出ます。

### セキュリティ

自分の端末で `haiku serve` を動かして自分で使う分には、以下の対策で守られています。

| 経路 | 状態 |
|---|---|
| 待ち受けアドレス | 既定で `127.0.0.1` のみ。LAN からも届きません |
| 他サイトの JS からの読み取り | CORS を開けていないため応答を読めません |
| DNS リバインディング | Host ヘッダを検証し、`localhost` / `127.0.0.1` / `::1` 以外を 400 で拒否します |
| API キーの露出 | サーバー側のみ。`/api/status` は有無だけを返します |
| 入力長 | 句・読みとも 200 文字で打ち切り（LLM への流し込み量を固定） |
| 検索結果リンク | `http` / `https` 以外のスキームは href に入れません |

DNS リバインディングは、攻撃者が自分のドメインを `127.0.0.1` に解決させて同一オリジン扱いに
持ち込む手口です。これを許すと、悪意あるページを開いただけで `/api/evaluate` を叩かれ、
**あなたの API キーで課金が発生します**。Host 検証はこれを塞ぐためのものです。

**残っているリスクは「認証が無いこと」だけです。** 外部公開する場合：

```bash
haiku serve --host 0.0.0.0 --allow-host haiku.example.com
```

`--host` をローカル以外にすると起動時に警告が出ます。到達できる相手は誰でもあなたの API キーで
評価を実行できるので、**必ず前段にリバースプロキシ等で認証を置いてください**。
レート制限も入れていないため、認証なしで公開すると青天井に課金されます。

### コスト

LLM 評価 1 回あたりの実測・概算です（`claude-opus-5` = 入力 $5 / 出力 $25 per MTok）。

| 項目 | トークン数 | 備考 |
|---|---|---|
| 入力：システムプロンプト | 約 500 | 固定 |
| 入力：構造化出力スキーマ | 約 1,000 | 固定 |
| 入力：句＋事前解析結果 | 約 350 | 句によらずほぼ一定 |
| **入力 合計** | **約 1,800** | **≈ $0.009** |
| 出力：講評・添削の JSON | 1,500〜2,500 | |
| 出力：思考（adaptive thinking） | **変動が大きい** | effort 設定に強く依存 |

**入力コストは無視できます。効く（＝支配的な）のは出力、とくに思考トークンです。**
Opus 5 は思考が既定でオンで、思考トークンも出力単価（$25/MTok）で課金されます。
既定の `effort: high` なら **1 回あたりおおむね $0.08〜0.20（十数円〜30 円程度）** を見込んでください。

> 出力側の数値は実測ではなく見積もりです（このリポジトリの検証環境に API キーが無く、
> 実際の応答を計測できていません）。初回実行時に画面下部へ実トークン数が表示されるので、
> そこで実費を確認してください。

コストを下げる手段：

- **思考の深さを下げる** — 画面の「AI の思考の深さ」、CLI は `--effort`。俳句一句の評価なら
  `medium` で十分なことが多く、`low` ならさらに安くなります。
- **モデルを変える** — `--model claude-sonnet-5`（入力 $3 / 出力 $15）。
- **AI を切る** — 画面のチェックボックス、CLI は `--no-llm`。歳時記照合・定型判定・
  ローカル類句照合は**無料**（API を一切呼びません）で動きます。推敲の初期段階はこれで十分です。
- **`batch` を使うときは注意** — 1 行 1 句すべてに LLM 評価が走ります。句数 × 上記単価です。

Web 検索（Tavily / Serper）は各社の無料枠内であれば追加費用はかかりません。
1 回の評価で最大 4 クエリ（句全体＋各節）を投げます。

### API

| メソッド | パス | 用途 |
|---|---|---|
| `GET` | `/` | 画面 |
| `GET` | `/api/status` | 有効な機能・季語件数（キーは返さない） |
| `POST` | `/api/analyze` | 定型・歳時記・類句チェック（LLM 抜き、即応答） |
| `POST` | `/api/evaluate` | LLM 評価・添削（数十秒〜数分） |
| `GET` | `/api/kigo` | 季語検索（`q` / `season` / `category` / `limit`） |
| `GET` | `/api/docs` | OpenAPI ドキュメント |

```bash
curl -X POST http://127.0.0.1:8000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"haiku":"古池や 蛙飛びこむ 水の音","use_web":false}'
```

## 各モジュールの中身

### ① 歳時記照合（`saijiki.py` / `db.py`）

`data/saijiki.json` に 341 件の季語を収録。季節は 春・夏・秋・冬・新年 の 5 区分、
分類は 時候・天文・地理・生活・行事・動物・植物 の 7 区分。`haiku build-db` で SQLite
（`data/saijiki.sqlite3`）に展開され、以降はそこから読みます。SQLite が無い場合は
JSON を直接読むため初回実行でも動作します。

判定内容：

- **季語の検出** — 見出し語・傍題・読みを最長一致で走査。`秋の暮` を `秋`+`暮` に
  分解せず一語として拾います。読みからの一致は誤検出しやすいため 3 音以上に限定し、
  一致経路（本文／読み）を出力に明示します。
- **季重なり** — 同じ季節の季語が複数 → 警告
- **季違い** — 異なる季節の季語が同居 → より強い警告（句の季節が定まらない）
- **季節外れ** — `--season` / `--date` で指定した季節と一致しない季語を指摘
- **注記** — 「朝顔は秋」「小春は冬」のような字面と季節が食い違う季語には備考を表示

### ② 客観的評価・添削（`evaluator.py`）

Anthropic API（既定 `claude-opus-5`）に構造化出力（JSON Schema）で問い合わせます。

- 配点は **構造 30 / オリジナリティ 35 / 情景と余韻 35** の 100 点満点
- 類想・陳腐な措辞・感情語の直叙・説明過多を減点対象として明示的に指示
- **伝統派（有季定型）** と **現代派** の講評を別々のフィールドで受け取り、
  両者を同じ結論に均さないようプロンプトで指示
- 添削案は方向性の異なる 2〜3 案。各案に「変更点／ねらい／留意点」を付与
- ①③ の解析結果をプロンプトに渡し、機械判定に誤りがあれば指摘させたうえで
  モデルの判断を優先させます

`--effort low|medium|high|xhigh|max` で思考の深さを、`--model` でモデルを変更できます。

### ③ 類似句チェック（`similarity.py`）

二系統で照合します。

- **ローカル照合（常時）** — `data/famous_haiku.json` の有名句 110 句と、
  文字 bigram の Dice 係数＋最長共通部分長で比較。**表記と読みの両方**で比較し
  高い方を採用します（「蛙」を「かわず」と読むか「かえる」と読むかで読みが割れるため、
  読みだけの比較では原句の丸写しを取り逃がします）。
- **Web 検索（キーがある場合）** — Tavily または Serper で、句全体の完全一致検索と
  各節のフレーズ検索を実行

リスク度は **高／中／低／判定不能** の 4 段階。句全体の完全一致（ローカル 85% 以上、
または Web 完全一致）で「高」、共通措辞やフレーズ単位の既出多数で「中」となります。

> ローカルコーパスは著作権保護期間の満了した作者を中心とした 110 句にすぎません。
> 「低」は「類句が存在しない」ことの証明ではなく、**この照合範囲では見つからなかった**
> という意味です。投句先の過去入選句集を `famous_haiku.json` に追加することを推奨します。

## 音数（モーラ）の数え方

`kana.py` が以下の規則で数えます。

- 拗音（ゃゅょ 等の小書き文字）は直前の音に含めて数えない — 「きょう」＝2 音
- 促音「っ」・撥音「ん」・長音「ー」はそれぞれ 1 音 — 「がっこう」＝4 音、「らーめん」＝4 音
- かな以外（漢字・記号・空白）は無視

漢字は janome（形態素解析）で読みを取ります。janome 未インストール時は歳時記の
見出し語＋常用語の内蔵辞書で最長一致し、読めない文字は警告として明示します
（黙って誤った音数を出しません）。

### 読みが合わないとき

形態素解析は現代語向けのため、文語の活用（例：「初むる」を「はつむる」と誤読）で
音数がずれることがあります。その場合は `--yomi` を使ってください。

```bash
# 節ごとに区切って渡すと各節の音数まで正確になる
haiku check "万緑の 中や吾子の歯 生え初むる" --yomi "ばんりょくの なかやあこのは はえそむる"
```

読みを一続きで渡した場合は総音数のみが正となり、各節はモーラ数で機械的に割ったうえで
その旨を警告します。

## 制約と既知の限界

- 歳時記データはモックです（341 件）。実運用では権利関係を確認のうえ正規の歳時記に
  差し替えてください。収録漏れの季語は「無季」と判定されます。
- 類句チェックの網羅性は保証されません。上記のとおり「低」は非存在の証明ではありません。
- LLM の採点は絶対評価ではなく、選者の主観を模したものです。同じ句でも実行ごとに
  数点は揺れます。順位付けの根拠ではなく推敲の材料としてお使いください。
- Web 検索は日本語俳句の索引網羅性に依存します。ヒットしないことは既出でないことを
  意味しません。

## 開発

```bash
pip install -e ".[dev,reading]"
pytest
```

```
src/haiku_checker/
├── kana.py         かな正規化・モーラ計算
├── reading.py      漢字→かな（janome / 内蔵辞書フォールバック）
├── db.py           歳時記の SQLite ストア
├── saijiki.py      ① 季語照合
├── structure.py    五七五分割と定型判定
├── evaluator.py    ② LLM 評価・添削
├── similarity.py   ③ 類似句チェック
├── analyzer.py     パイプライン統合（歳時記・照合器・リーダーをキャッシュ）
├── report.py       ターミナル表示
├── cli.py          CLI
└── web/
    ├── app.py             FastAPI（CLI と同じ解析モジュールを利用）
    └── static/index.html  フロントエンド（依存ライブラリなし）
```

歳時記データを書き換えたら `haiku build-db` を実行してください。サーバー常駐中に
差し替える場合は `analyzer.clear_cache()` でキャッシュを破棄できます。
